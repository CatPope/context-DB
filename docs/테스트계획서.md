## 1. 목적 및 배경

- context-DB는 그동안 사람이 수동으로 하던 **맥락 수집 작업**(메신저 채팅 최신순 열람·웹 문서 확인·받은파일·서버정보 취합)을 **자동 적재 + 질의**로 대체한다.
- 따라서 본 계획서는 **"기존 수집 방식(브리핑 워크플로우)을 context-DB가 동일하게(더 빠르게) 재현하는가"** 를 핵심 시험 축으로 삼는다.
- 단위/무결성 검증은 자동화 스위트(`테스트보고서.md`, 25 PASS)가 담당하고, 본 계획은 **수집 소스 충실성 + 에이전트 회수 시나리오**를 중점 검증한다.

## 2. 시험 대상 및 범위

| 컴포넌트 | 시험 대상 |
|---|---|
| Schema/DDL | 테이블·제약·인덱스·FTS5·트리거·시드 |
| Ingest(`ingest.py`) | 메신저 로그 파서·정규화·중복처리·받은파일/웹 문서 링크 |
| Query(`cli.py` 조회) | search/timeline/by-tag/by-person/links/projects/sources/stats, `--json` |
| Skill(`context-db.skill.md`) | 에이전트 읽기전용 회수 흐름·사용규칙 |
| 운영 | init/ingest/watch/set-project/tag, 스케줄러 |

- **범위 외(차기)**: 의미(벡터) 검색, 웹 문서/파일 본문 추출, 웹 UI, 멀티유저/권한.

## 3. 시험 환경

- OS: Windows 11 / Python 3.13 (내장 SQLite **FTS5 포함**) / 표준 라이브러리만.
- ⚠️ 독립 `sqlite3.exe`(3.42)에는 FTS5가 없어 `sqlite3 < schema.sql` 실패 → 스키마·적재는 **Python 경로**(`context-db init`/`ingest`)로만.
- 격리 원칙: 쓰기 시험은 **임시 DB(`--db <tmp>`)** 로 수행, 운영 `context.db` 불변.

## 4. 시험 데이터 — 기존 수집 방식 연계 (핵심)

기존 브리핑에서 모으던 **실제 소스**를 그대로 시험 입력으로 사용한다.

| 수집 소스(기존 방식) | 실제 위치/형식 | context-DB 적재 대상 |
|---|---|---|
| 메신저 채팅(채널 폴더별) | `메신저 채팅저장/<채널>/<YYYY-MM-DD>.txt`, 헤더 `[YYYY-MM-DD 오전/오후 H:MM] 이름` + 멀티라인 | SOURCE(messenger) + CONTEXT_ITEM |
| 메신저 받은파일 | `메신저 받은파일/*`(PDF/PPTX/HWP…) | SOURCE(file) + LINK(파일 경로) |
| 공유 웹 문서(탭 구분) | `docs.google.com/document/d/...` | SOURCE(web_doc) + LINK |

**실데이터 규모(관측)**: 채널 18 · context_item 610 · person 16 · link 90(받은파일 89 + 웹 문서 1). 채널 예: 피지컬 AI 관련(`[피지컬 AI]`/작업 채팅/환경 구성/AI 플랫폼 팀), 블록체인, 개인 DM(홍길동·유관순·이순신 등), 그룹.

**로그 형식 특이사항(파서 시험 포인트)**: 오전/오후 12시간제 시각, 멀티라인 본문(빈 줄 포함), 시스템 라인(`…다운로드를 완료했습니다`), 첨부 파일명 단독 라인, `(이모티콘)`, 동일 분 내 반복 발화.

## 6. 시험 방법

1. **자동화 스위트**: `python tests/test_context_db.py`(격리 합성 로그, 결정적). 단위·트리거·회귀 담당.
2. **skill 기반 시나리오(실데이터)**: 운영 `context.db` 에 대해 §5-C 명령을 `--json`으로 실행, 반환 맥락의 정확성·범위 확인(읽기전용).
3. **운영/적재**: 임시 DB(`--db <tmp>`)로 init→ingest→재ingest(멱등)→set-project→tag 전 생애주기.

## 7. 합격 기준 (Entry / Exit)

- **Entry**: 스키마 생성 성공, 실데이터 1회 적재 완료(`stats.context_item > 0`).
- **Exit**: (a) 자동화 스위트 전건 PASS, (b) §5-C 시나리오 전건 유효 결과, (c) `fts_in_sync=True`·`orphan_items=0`, (d) 재적재 멱등, (e) 알려진 한계는 문서화됨.

## 1. 테스트 환경
- OS: Windows 11
- Python: 3.13.3 / 내장 SQLite: **3.49.1 (FTS5 포함)**
- 별도 패키지 없음(표준 라이브러리)
- 방식: 임시 폴더에 가짜 채팅 로그를 생성해 격리 검증(실 `context.db` 불변) + 실데이터 스모크

> 참고(환경 특이사항): 독립 `sqlite3.exe`(CLI, 3.42)에는 FTS5가 없어 `sqlite3 context.db < schema.sql`이 실패한다. 스키마 생성·적재는 **Python 경로**(`context-db init`/`ingest`)로 수행하며, 본 테스트도 Python 기준이다.

## 6. 알려진 한계 / 후속 권고
- **한국어 FTS 검색은 토큰 단위**: 조사·붙임 때문에 부분문자열 검색이 제한된다(상위설계서 §10 위험과 일치). 완화책 — 사용자에게 접두어(`키워드*`) 안내, 또는 차기 확장으로 `unicode61`/트라이그램(`trigram`) 토크나이저·의미(벡터) 검색 도입.
- **sqlite3 CLI에 FTS5 없음**: 스키마/적재는 Python 경로로 통일(문서화 완료).
- **백그라운드 watch는 세션 스코프**: 상시 운영은 `scheduler-register.bat`(작업 스케줄러) 권장.
- **동시성**: watch 상시 쓰기 환경에서 `PRAGMA journal_mode=WAL` 적용 시 읽기/쓰기 경합 감소(미적용, 제안).
